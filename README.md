# LOCKIN

Android focus enforcement. During a focus session every app except your allowlist is covered by a full-screen block
screen, and leaving early means writing out why. 100% local: release builds have no `INTERNET` permission, no
analytics, no accounts, no backups.

Android only (minSdk 24, targetSdk 36). Expo SDK 58 + a Kotlin native module (`modules/focus-enforcement`).
`android/` and `ios/` are generated by `expo prebuild` (Continuous Native Generation) and never committed.

## Variants

One codebase, selected by `APP_VARIANT` in `app.config.ts`. Both install side by side.

| | `play` | `hardline` |
| --- | --- | --- |
| Package | `com.CHANGEME.lockin` | `com.CHANGEME.lockin.hardline` |
| Name / icon | LOCKIN, white padlock | LOCKIN HL, red padlock |
| Purpose | Store-safe candidate | Personal sideload |
| Primary detector | UsageStatsManager events, polled every 500 ms during sessions | AccessibilityService (UsageEvents as fallback) |
| Accessibility | Optional, window-state events only, package name only, never acts | Primary; also reads Settings window titles |
| Settings | Always reachable | Reachable, except App info for LOCKIN HL, Accessibility, Device admin, Force stop/Uninstall during sessions |
| Uninstall guard | — | Device admin (one-tap uninstall blocked) |
| Device Owner (optional) | — | Suspends blocked apps, blocks own uninstall, disables safe boot; all reverted at session end |
| Battery exemption | Opens battery settings list | Asks directly (`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`) |

The variant reaches Kotlin as `<meta-data android:name="lockin.variant">`, written by `plugins/withLockin.js`, which
also injects the hardline-only device-admin receiver.

**Before the first build:** replace `CHANGEME` in `app.config.ts` (`BASE_PACKAGE`). Changing the package later means
new keystores and a reinstall.

## Build profiles (`eas.json`)

| Profile | Variant | Output | Network permissions |
| --- | --- | --- | --- |
| `development` | play | dev client APK | kept (Metro needs them) |
| `development-hardline` | hardline | dev client APK | kept |
| `preview` | play | internal APK | **blocked** |
| `preview-hardline` | hardline | internal APK | **blocked** |
| `production` | play | AAB (store) | **blocked**, defined but unused |

`LOCKIN_BLOCK_NETWORK=1` (set by the non-dev profiles) adds `INTERNET` and `ACCESS_NETWORK_STATE` to
`android.blockedPermissions`, which strips them from the merged manifest.

Signing: EAS keeps one managed keystore per application ID, reused by every profile of that package. Keep the play
keystore; it becomes the Play upload key later.

## First-time setup

```sh
npm install
npx eas-cli login
npx eas-cli init          # creates the EAS project "lockin"
```

`eas init` can't write into a dynamic config. Paste the project ID it prints into `EAS_PROJECT_ID` in
`app.config.ts` and commit it.

## Build and install

```sh
npx eas-cli build -p android --profile development-hardline   # dev client, hardline
npx eas-cli build -p android --profile preview-hardline       # sideload APK, hardline
npx eas-cli build -p android --profile preview                # sideload APK, play
```

The first build of each package asks to generate a keystore: answer yes (EAS-managed).

Install from the link EAS prints (or the build page QR code): open it on the phone → download the APK → allow
"Install unknown apps" for the browser when asked → Install. Then open LOCKIN and follow the permissions screen.
Android 13+ will call the accessibility toggle a "Restricted setting" for a sideloaded APK; the app walks you through
App info → ⋮ → Allow restricted settings.

Dev client loop (after installing a development build):

```sh
npm run dev            # play
npm run dev:hardline   # hardline
```

Native code changes (Kotlin, plugin, `app.config.ts`) need a new development build. When switching variants locally
with `npx expo prebuild`, always use `--clean`.

Checks:

```sh
npm run typecheck
scripts/verify-release.sh path/to/build.apk   # see below
```

## Verifying a release artifact

`scripts/verify-release.sh` dumps the merged manifest and fails if `INTERNET`, `ACCESS_NETWORK_STATE` or
`QUERY_ALL_PACKAGES` is requested or `allowBackup` isn't `false`. It needs `apkanalyzer` or `aapt2` from the Android
SDK (`ANDROID_HOME`), or `bundletool` for `.aab`.

```sh
# Download the artifact from the EAS build page ("Download build"), or:
npx eas-cli build:list --platform android --limit 5        # find the build + artifact URL
curl -L -o lockin-hl-preview.apk "<artifact URL>"
scripts/verify-release.sh lockin-hl-preview.apk
```

## Device Owner (hardline, optional, spare phone only)

Device Owner can only be set on a device with **no accounts and no extra users**. Easiest: factory reset, skip
every account step in setup, then:

```sh
# 1. Install the hardline APK (preview-hardline) and open it once.
# 2. Settings → Accounts: remove every account (Google, Samsung, …). Remove secondary users / work profiles.
adb shell dpm set-device-owner com.CHANGEME.lockin.hardline/expo.modules.focusenforcement.LockinDeviceAdminReceiver
```

If it says "already some accounts on the device", an account is still present (some OEMs keep a hidden one; a reset is
then the only way).

Check: LOCKIN HL → Settings shows "Device Owner: ON". During sessions it then also suspends blocked apps, blocks its
own uninstall and disables safe boot. All of it is reverted on session end, expiry, and when an emergency unlock
completes.

### Rollback

1. End or wait out any running session (emergency unlock if needed: 15 minutes).
2. LOCKIN HL → Settings → **Release device controls**. This calls `clearDeviceOwnerApp` and deactivates device admin.
   (`adb shell dpm remove-active-admin` does **not** work: Android only allows it for test-only apps.)
3. Uninstall LOCKIN HL normally. Re-add your accounts.
4. If the app can't be opened (crash, lost build), the only way out is a factory reset. Check that suspended apps
   come back: `adb shell pm list packages -u` and launch them; `adb shell dumpsys device_policy` should not list
   LOCKIN HL.

Without Device Owner, just deactivate "LOCKIN HL" under Settings → Security → Device admin apps (outside a session),
then uninstall.

## Layout

```
app.config.ts                 variants, permissions, plugins
plugins/withLockin.js         variant meta-data, backup rules, <queries>, hardline-only components
modules/focus-enforcement/    Expo module: Kotlin enforcement + typed JS API (index.ts)
src/app/                      expo-router screens
src/data/                     expo-sqlite + migrations (src/data/migrations)
scripts/verify-release.sh     release manifest check
docs/                         DEVICE_TEST.md, PLAY_POLICY.md, PHASES.md
```
